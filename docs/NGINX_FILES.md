# Владение и reconciliation Nginx-файлов `nginx-telego`

[**Русский**](NGINX_FILES.md) · [English](NGINX_FILES_EN.md)

Этот документ фиксирует итоговый контракт **P6 — Managed Nginx File Ownership** и **P7 — Reconciliation Engine**. P6 отвечает за однозначное владение и диагностику drift, P7 — за безопасное приведение package-owned/generated состояния к desired state из UCI.

## Source of truth

Пользовательская конфигурация ingress хранится в:

```text
/etc/config/nginx_telego
```

Versioned ownership registry:

```text
/usr/share/nginx-telego/ownership.tsv
```

Canonical package copies статических файлов:

```text
/usr/share/nginx-telego/templates/
├── 20-telego-core.conf
└── telego.locations
```

Активный файл не становится эталоном после ручного редактирования. Для `package` эталоном остаётся canonical copy, для `generated` — UCI/runtime state renderer.

## Registry v3

`ownership.tsv` содержит пять TAB-separated полей:

```text
path    role    ownership    presence    source
```

Финальный layout P7:

| Path | Role | Ownership | Presence | Source |
|---|---|---|---|---|
| `/etc/nginx/conf.d/20-telego-core.conf` | `core` | `package` | `required` | `/usr/share/nginx-telego/templates/20-telego-core.conf` |
| `/etc/nginx/snippets/telego.locations` | `locations` | `package` | `required` | `/usr/share/nginx-telego/templates/telego.locations` |
| `/etc/nginx/conf.d/80-telego-ingress.conf` | `ingress` | `generated` | `conditional` | `renderer` |
| `/etc/nginx/conf.d/85-telego-fallback.conf` | `fallback` | `generated` | `conditional` | `renderer` |

`nginx-telego` не объявляет весь `/etc/nginx/conf.d/` своей собственностью. Неизвестные файлы остаются administrator/application-owned.

## Ownership

### `package`

Статический active file имеет canonical package copy. Состояния:

| State | Значение |
|---|---|
| `ok` | active file совпадает с canonical copy |
| `modified` | regular file изменён вручную |
| `missing` | active file отсутствует |
| `invalid-type` | active path — symlink, directory, FIFO или другой неподдерживаемый тип |
| `source-missing` | canonical package source отсутствует |
| `source-invalid-type` | canonical source имеет небезопасный тип |

P7 автоматически восстанавливает только безопасный drift `modified`/`missing`. Unsafe types и повреждённый canonical source блокируют reconciliation.

### `generated`

Generated files создаются renderer и должны содержать общий marker:

```text
# Generated by /usr/libexec/nginx-telego-render from /etc/config/nginx_telego.
```

и role marker:

```text
# nginx-telego-role: ingress
```

или:

```text
# nginx-telego-role: fallback
```

Таким образом файл с правильным общим marker, но неправильной ролью не принимается как owned. Он классифицируется `foreign`.

Для плавной миграции P7 принимает прежние role-lines из ранней P7-реализации только для той же роли и при следующем render переписывает их в canonical marker.

Generated states:

| State | Значение |
|---|---|
| `absent` | conditional file отсутствует |
| `managed` | regular file имеет общий marker и marker правильной роли |
| `foreign` | regular file занимает reserved path, но ownership не доказан |
| `invalid-type` | reserved path имеет неподдерживаемый тип |

## Read-only inventory

```sh
/usr/libexec/nginx-telego-files validate
/usr/libexec/nginx-telego-files list
/usr/libexec/nginx-telego-files status
```

`status` возвращает:

```text
path    role    ownership    presence    state    source
```

Helper остаётся read-only: он не делает `rm`, `mv`, rewrite, reload или UCI mutation.

## Reconciliation Engine

Обычный apply-path:

```text
LuCI / uci commit
        ↓
procd config.change
        ↓
/etc/init.d/nginx-telego reload
        ↓
/usr/libexec/nginx-telego-reconcile apply
```

Reconciler выполняет одну транзакцию:

```text
lock
 ↓
validate registry + inventory
 ↓
backup managed state
 ↓
repair safe package drift
 ↓
migrate owned legacy paths
 ↓
renderer apply --no-reload
 ↓
final nginx -t
 ↓
reload only if filesystem changed
 ↓
commit
```

При ошибке renderer, `nginx -t` или reload filesystem state откатывается к pre-transaction состоянию.

Одновременно может работать только один reconciler. Active lock блокирует второй apply; stale lock восстанавливается автоматически.

## Legacy migration

P7 автоматически обрабатывает два исторических пути.

### `/etc/nginx/conf.d/zz-telego-managed.conf`

Старый combined generated file удаляется/мигрирует только если содержит historical package marker. Foreign regular file сохраняется. Symlink/directory/FIFO блокируют автоматическую миграцию.

### `/etc/nginx/conf.d/telego.conf`

Старый static core автоматически удаляется только когда его bytes совпадают с canonical core. Изменённый regular file сохраняется и блокирует automatic migration, чтобы пользовательские изменения не были молча потеряны. Unsafe type также блокирует migration.

После успешной P7 migration активный layout использует только `20-*`, `80-*`, `85-*` и `telego.locations`.

## Uninstall

Удаление generated state также проходит через reconciler:

```sh
/usr/libexec/nginx-telego-reconcile remove-generated
```

Package `prerm` использует этот путь вместо прямого mutation через renderer. Поэтому LuCI/procd/uninstall разделяют один lock и один outer `nginx -t`/rollback boundary.

Foreign files на reserved paths не удаляются.

## Security boundary registry

Registry не является произвольным root-filesystem manifest. Проверяются:

- абсолютные clean paths без `..`, `.` и пустых segments;
- `core`, `ingress`, `fallback` только как direct child `/etc/nginx/conf.d/*.conf`;
- `locations` только как direct child `/etc/nginx/snippets/`;
- package sources только в `/usr/share/nginx-telego/templates/`;
- допустимые `role / ownership / presence` combinations;
- отсутствие duplicate managed paths;
- обязательный source.

Write-path P7 использует только уже проверенный namespace P6.

## CI

Контракт проверяется на нескольких уровнях:

1. ownership tests: drift, source failure, symlink/directory/FIFO, path boundary и role markers;
2. renderer tests: Cloudflare/Native contracts, conflicts, role-aware ownership и atomic rollback;
3. reconciler tests: package repair, core/generated migration, reload/nginx-test rollback, foreign files, fallback transition, active/stale lock, uninstall path;
4. APK layout: финальные package paths, modes, ownership и отсутствие legacy/generated payloads;
5. OpenWrt rootfs smoke: реальный APK, `nginx-telego-files validate/status`, legacy migration, remove/reinstall lifecycle.

## Граница P8

P6/P7 управляют только файлами, ownership которых принадлежит `nginx-telego`, и безопасно сохраняют foreign state. P8 добавит LuCI inventory и явные administrator operations для custom/foreign `.conf`: disable/quarantine, restore, delete, diff, repair и дальнейший restricted editor. До P8 чужой файл не удаляется и не принимается в ownership автоматически.
