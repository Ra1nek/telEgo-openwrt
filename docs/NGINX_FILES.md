# Владение Nginx-файлами `nginx-telego`

[**Русский**](NGINX_FILES.md) · [English](NGINX_FILES_EN.md)

Этот документ описывает контракт **P6 — Managed Nginx File Ownership**. Его задача — однозначно определить, какие Nginx-файлы принадлежат `nginx-telego`, какие из них генерируются автоматически и как обнаруживается ручное изменение файлов.

P6 намеренно **не изменяет** файлы автоматически. Он только строит надёжный inventory и классифицирует drift. Repair, disable, restore, delete и reconciliation относятся к следующим этапам и должны использовать общий транзакционный путь с `nginx -t` и rollback.

## Source of truth

Пользовательская конфигурация ingress хранится в UCI:

```text
/etc/config/nginx_telego
```

Список файлов, которыми владеет пакет, задаёт versioned registry:

```text
/usr/share/nginx-telego/ownership.tsv
```

Canonical package copies для статических Nginx-файлов находятся вне активного include tree:

```text
/usr/share/nginx-telego/templates/
├── telego.conf
└── telego.locations
```

Активный файл никогда не становится эталоном только потому, что его изменили вручную. Для package-owned файлов эталоном остаётся canonical copy из `/usr/share/nginx-telego/templates/`.

## Registry v1

`ownership.tsv` содержит пять TAB-separated полей:

```text
path    role    ownership    presence    source
```

Текущий registry описывает:

| Path | Role | Ownership | Presence | Source |
|---|---|---|---|---|
| `/etc/nginx/conf.d/telego.conf` | `core` | `package` | `required` | `/usr/share/nginx-telego/templates/telego.conf` |
| `/etc/nginx/snippets/telego.locations` | `locations` | `package` | `required` | `/usr/share/nginx-telego/templates/telego.locations` |
| `/etc/nginx/conf.d/zz-telego-managed.conf` | `ingress` | `generated` | `conditional` | `renderer` |

Имена активных generated-файлов могут измениться до stable release. Registry является контрактом ownership, а не обещанием навсегда сохранить конкретное имя `zz-telego-managed.conf`.

## Типы ownership

### `package`

Файл имеет canonical package copy и может быть восстановлен из неё в будущем P7.

Ручное изменение активного файла считается drift. Оно не принимается как новая конфигурация пакета.

### `generated`

Файл создаётся renderer из UCI/runtime state. Для generated ingress ownership подтверждается точным marker:

```text
# Generated by /usr/libexec/nginx-telego-render from /etc/config/nginx_telego.
```

Файл на reserved path без этого marker считается `foreign`.

## Presence

`required` означает, что файл ожидается всегда при установленном `nginx-telego`.

`conditional` означает, что файл может отсутствовать, если соответствующая managed-функция выключена.

## Состояния package-owned файлов

| State | Значение |
|---|---|
| `ok` | active file совпадает с canonical package copy |
| `modified` | active file — regular file, но содержимое изменено |
| `missing` | active file отсутствует |
| `invalid-type` | active path существует, но это не обычный regular file; symlink всегда относится сюда, включая dangling symlink |
| `source-missing` | canonical package copy отсутствует |
| `source-invalid-type` | canonical source существует в небезопасном типе, например symlink или directory |

Ошибка canonical source имеет приоритет: будущий Repair не должен пытаться восстанавливать active file из повреждённого source.

## Состояния generated ingress

| State | Значение |
|---|---|
| `absent` | generated path отсутствует; это нормально при выключенном профиле |
| `managed` | regular file содержит точный renderer marker |
| `foreign` | regular file занимает managed path, но не принадлежит renderer |
| `invalid-type` | path является symlink, directory, FIFO или другим неподдерживаемым типом |

`foreign` принципиально отличается от `managed`: пакет не должен автоматически считать чужой файл своим только из-за совпадения имени.

## Security boundary registry

Registry не является произвольным списком root filesystem paths. Helper проверяет:

- абсолютные пути без `..`, `.` и пустых path segments;
- `core` и `ingress` только как direct child `/etc/nginx/conf.d/*.conf`;
- `locations` только как direct child `/etc/nginx/snippets/`;
- package sources только как direct child `/usr/share/nginx-telego/templates/`;
- допустимые пары `role / ownership / presence`;
- отсутствие duplicate managed paths;
- обязательный `source` для каждой записи.

Это важно до появления write-операций: P7 должен получить уже ограниченный и однозначный namespace ownership.

## Read-only helper

P6 устанавливает:

```text
/usr/libexec/nginx-telego-files
```

Поддерживаются команды:

```text
nginx-telego-files validate
nginx-telego-files list
nginx-telego-files status
```

`validate` проверяет registry.

`list` выводит registry после проверки.

`status` возвращает по одной TAB-separated строке на managed path:

```text
path    role    ownership    presence    state    source
```

Helper не выполняет `rm`, `mv`, rewrite, reload Nginx или изменение UCI.

## Что происходит с другими `/etc/nginx/conf.d/*.conf`

P6 **не объявляет весь `/etc/nginx/conf.d/` собственностью telEgo**. Файлы других приложений и администратора остаются вне registry.

Будущий LuCI Nginx Files inventory сможет показывать их как custom/foreign и управлять ими отдельными безопасными операциями, но package-owned repair не должен затрагивать такие файлы автоматически.

## Проверки CI

P6 проверяется на трёх уровнях:

1. Unit/integration fixture проверяет registry, drift, symlink/directory/FIFO и path-boundary cases.
2. APK layout check извлекает собранный `nginx-telego` APK и проверяет наличие, mode и root ownership registry/templates/helpers.
3. OpenWrt rootfs smoke устанавливает реальный APK на поддерживаемые OpenWrt 25.12.x releases и проверяет установленную файловую структуру.

## Граница P6 и P7

P6 отвечает на вопрос:

> Какие Nginx-файлы принадлежат `nginx-telego` и в каком они состоянии?

P7 будет отвечать на следующий вопрос:

> Как безопасно привести реальное состояние файлов к desired state из UCI?

До P7 состояние `modified`, `missing`, `foreign` или `invalid-type` является диагностикой, а не автоматическим запросом на изменение filesystem.
